# 文档处理

## 处理管线

普通文档上传后会经过以下阶段：

```text
原始文件
  -> 文本与图片内容提取
  -> 文本分块
  -> 实体抽取
  -> 关系抽取与权重计算
  -> 知识融合
  -> 图谱布局与社区页面生成
  -> 向量库持久化
```

处理状态按文本块保存，前端持续展示分块数、百分比、单块耗时和预计剩余时间。

## 文本分割器

通过环境变量为扩展名选择分割器：

```dotenv
SIMPLE=[txt,pdf]
SEMANTIC=[]
CHARACTER=[md]
```

同一个扩展名应只配置在一种分割器中。未匹配到的扩展名会回退到默认分割器。

## 暂停与恢复

暂停请求不会中断正在执行的模型请求，而是在当前文本块完成后保存检查点。恢复任务时，系统从上次已完成位置继续，并保留已有抽取结果。

## 增量更新

重新上传同名且已完整处理的文件时，系统会进入增量更新流程。更新后的文档、向量数据和图谱会保持一致，并自动重新绘制图谱。

如果同名文件上次处理失败，系统会先清理残留数据，再执行完整处理，不会误用不完整结果增量更新。

## 处理失败

常见原因包括模型配置缺失、模型输出不是有效 JSON、请求超时、嵌入模型不可用或 PDF 视觉服务未配置。开启备用 AI 后，主模型失败时系统会尝试继续当前文本块。
